# 0.3.17 — 사진을 유지한 배포 용량 감소

[English](../../en/releases/0.3.17.md) · [웹사이트](https://windsahead.com/ko) · [콘텐츠 갱신](0.3.16.md) · [용량 근거](../../research/2026-10-31-deployment-budget.json) · [PR #58](https://github.com/developdh/Winds-Ahead/pull/58)

공개 후 보완: 실제 호스팅은 `_redirects`를 적용하지 않아 [v0.3.18](0.3.18.md)에서 이전 사진 주소를 실제 호환 파일로 복원합니다. 아래 301 결과는 로컬 Wrangler 검증입니다.

v0.3.16 콘텐츠 갱신이 Sites의 압축 해제 용량 제한을 넘었습니다. 사진을 다시 인코딩하지 않고 배포 묶음을 줄여 글로벌 11종·중국 3종, 새 참고 사진 19개와 강호령 종료 정정을 모두 유지합니다.

바이트가 완전히 같은 전체 사진 네 쌍은 파일을 공유해 708,038바이트를 줄이고 기존 주소에는 영구 리디렉션을 둡니다. 외관별 원본 인덱스·설명·미리보기 구도·출처 링크는 각각 유지합니다. 전체 조사·권리·검수 기록은 Git에 남기며, 빌드에서는 화면이 쓰지 않는 감사 필드만 제외하고 반복 문구를 JavaScript에 한 번 저장합니다. 표시 값·출처 설명·획득 원문·영상은 보존합니다. 클라이언트 도감 청크는 2,464,690에서 1,396,468바이트로 감소했습니다. 빌드 파일의 원시 용량 비교이며 실제 페이지 로딩 측정 결과는 아닙니다.

표준 형식의 후보 tar는 헤더를 포함해 압축 해제 시 267,233,280바이트로, 이전 271,076,864보다 줄어 256 MiB 제한 아래 1,202,176바이트의 여유를 확보했습니다. 새 사전 검사와 CI는 발행 전 압축 해제 tar 전체를 계산합니다. 대응하는 릴리스 절차는 태그 전에 실제 배포 묶음을 검사하고 macOS 메타데이터를 제외하도록 보완했습니다. 다음 콘텐츠 갱신도 용량을 다시 확인해야 합니다.

타입, 테스트 50개, 콘텐츠·사진·출처 검증, 예상 이력 불변 검사, 저장소 루트 Worker 빌드와 신·구 압축 파일의 통과·실패 검사를 확인했습니다. 새 계약 테스트 6개는 전체 외관·출처·일정·갤러리·서버별 획득 선택과 문자열 공유 결과를 검증합니다. 인앱 Chromium에서 한국어 모바일 상세·출처 기록, 영문 PC 공유 사진 갤러리와 개별 원본 링크, 커뮤니티 위키 상세 로드, 기존 이펙트 영상 재생, 11월 캘린더의 KO→EN 상태 보존을 확인했습니다. 해당 390px·1440px 화면에 가로 넘침은 없었습니다. 리디렉션 네 개가 인식됐고 이전 호박등 전체 사진 주소는 301로 이동했습니다. [UI 근거](../../research/2026-10-31-deployment-ui/results.json).

수량은 외관 755개, 외관 509개에 사진 905개로 유지됩니다. 기존 큰 청크·프레임워크 경고와 v0.3.16 검증 한계는 남습니다. 실제 기기·Firefox·WebKit·느린 네트워크·실사용 성능·초기 JavaScript 200 KB 목표는 새로 측정하지 않았습니다. 사이트 발행은 GitHub 릴리스와 별도로 확인하며 발행된 v0.3.16 태그는 유지합니다.
