# 콘텐츠·데이터·예상 정책 v0.1

[English](../en/content-model.md) · [제품 기획](product-plan.md)

이 문서는 구현을 위한 제안 모델입니다. 실제 도감 데이터나 검증 완료된 예측 모델은 아직 없습니다.

## 1. 데이터 구조

번역이 달라져도 하나의 외관은 하나의 안정적인 ID를 갖습니다. 이름으로 중국·글로벌 항목을 자동 합치지 않습니다. 같은 세트의 의상·헤어·무기, 체형별 모습과 염색 변형을 표현할 수 있어야 합니다.

| 개체 | 주요 정보 | 관계·주의점 |
| --- | --- | --- |
| Cosmetic | ID, 종류, 중국어 원명, 태그, 구성품 ID | 개별 품목과 세트 관계를 분리 |
| Localization | 외관 ID, 언어, 표시명, 설명, 별칭, 번역 상태, 명칭 출처 | `official`, `provisional`, `missing`; 중문 원명은 별도 보존 |
| Variant | 외관 ID, 체형, 스타일, 염색 여부 | 확인된 변형만 제공; 지원 여부 미확인은 null |
| RegionalRecord | 외관 ID, CN/Global, 지역·플랫폼 적용 범위, 버전, 출시 상태, 획득 가능 상태 | 언어와 서버는 독립적; 상태별 근거 연결 |
| Acquisition | 지역 기록 ID, 방식, 금액, 재화, 조건, 시작·종료, 출처 | 글로벌 값을 중국 값에서 자동 복제하지 않음 |
| ReleaseEvent | 이벤트 ID, 지역 기록 ID, 최초 출시/복각/종료, 날짜·기간, 정밀도, 출처 | 복수 이벤트로 판매·복각 이력 보존 |
| Forecast | 외관 ID, Global 대상 범위, 예상 기간/버전, 근거 수준, 이유, 전제, 작성·검토일, 검토 예정일, 상태 | 공식 ReleaseEvent와 별도 저장 |
| Source | URL, 게시자, 출처 등급, 언어, 대상 서버, 원문 게시일, 확인 시각, 판독 범위 | 원문의 주장과 운영자 해석 구분 |
| Evidence | 대상 개체/필드, Source ID, 페이지 내 위치·영상 시점, 검토자 | ‘어떤 출처가 어떤 값을 뒷받침하는지’ 연결 |
| Media | 외관/변형 ID, 이미지·영상 종류, URL/파일 참조, 원문, 제공자, 서버·버전, 재사용 근거, 양언어 대체 텍스트 | 표시 가능한 자산과 출처 링크만 가능한 자산 구분 |
| Revision | 대상 ID, 변경 전후, 이유, 근거 ID, 편집자, 기록 시각 | 정정·예상 철회·공식 전환 이력을 보존 |

공개 초안에 필요한 최소 정보는 안정적 ID, 중국어 원명 또는 검증된 공식명, 종류, 양언어 설명/이름 상태, 서버별 확인 범위, 출처, 확인일, 사용 가능한 대표 미디어입니다. 미디어 권한·내용 검증을 끝내지 못한 기록은 편집 초안으로 남깁니다. 상세의 모르는 값은 null로 두고 ‘미확인’으로 표시하며 0, 무료, 불가로 대체하지 않습니다.

## 2. 서버 상태와 적용 범위

- 편집 전용 `not_reviewed`: 글로벌 조사 전. 이용자에게 ‘글로벌 미발표’로 공개하지 않습니다.
- 공개 출시 상태: `unannounced`, `announced`, `released`. ‘미발표’는 확인일 기준 검토한 출처의 범위에서만 주장합니다.
- 별도 획득 가능 상태: `unknown`, `upcoming`, `available`, `ended`. 게임 내 확인 없이 오래된 판매 정보를 현재 판매 중으로 단정하지 않습니다.
- 중단·일정 취소는 해당 이벤트의 상태와 이유로 보존합니다. 공식 취소 자료 없이 ‘글로벌 출시 안 함’으로 표시하지 않습니다.
- 각 글로벌 기록에 공지가 적용되는 지역·플랫폼을 둡니다. 언어가 한국어라는 이유만으로 한국 전용 서버로 간주하지 않습니다. 적용 범위를 확인하지 못하면 그 한계를 표시합니다.

## 3. 날짜와 시간

- 공지 게시일, 게임 내 시작일, 판매 종료일, 자료 확인일을 별도 저장합니다.
- 날짜 정밀도는 `instant`, `day`, `window`, `month`, `version`, `unknown`으로 구분합니다.
- 시간이 명시된 일정은 원문 시간대/오프셋과 원문 문자열을 보존하고, 확인된 시각을 UTC로 저장합니다. 화면에서 사용자 시간대로 변환합니다.
- 시간대가 불명확하면 임의로 UTC+8을 붙이지 않습니다. 날짜만 있는 공지는 자정 UTC로 만들지 않으며 그 날짜를 유지합니다.
- 시작·종료의 포함 여부와 점검 종료 후 시작 같은 조건을 보존합니다. 원문의 날짜 범위와 구현의 반개방 구간 표현을 혼동하지 않습니다.
- 예상 월·버전은 날짜형 입력에 맞추기 위해 1일·말일로 변환하지 않습니다. 날짜 범위가 있으면 실제 범위만 그립니다.

## 4. 출처 등급과 확인 절차

| 등급 | 자료 | 사용할 수 있는 범위 |
| --- | --- | --- |
| A | 공식 홈페이지·공지·공식 채널에서 연결된 계정 | 해당 공지의 서버·지역·버전에 대한 사실 |
| B | 촬영 서버·날짜를 확인한 직접 플레이 기록, 허가받은 제작자 자료 | 보이는 외형·게임 내 관찰 정보; 공식 글로벌 예정일의 대체 근거는 아님 |
| C | 커뮤니티 글·재게시·요약 | 조사 단서; 단독으로 출시 확정 배지를 부여하지 않음 |

출처의 공식성은 미디어 재배포 권한과 별개입니다. 검색 결과 제목·URL의 날짜만으로 출시일을 정하지 않습니다. 글로벌 공식 공지는 영어·한국어를 교차 확인하되 한 언어만 먼저 발표됐을 수도 있습니다.

이미지 공지는 원본을 직접 확인한 뒤 필요한 필드를 기록합니다. OCR 결과는 초안이며 이름·재화·숫자·시간대는 사람이 대조합니다. 원문에 있는 미리보기/개발 중 표시도 전달합니다. 읽지 못한 이미지의 내용을 확인된 사실로 취급하지 않습니다.

상충하는 자료는 최신이라는 이유만으로 덮어쓰지 않습니다. 서버·지역·복각 여부를 비교하고, 해결될 때까지 문제 필드를 ‘확인 중’으로 표시합니다. 삭제된 원문은 출처 상태에 기록하고 허용된 대체 근거를 찾습니다.

## 5. 글로벌 예상 일정

### 초기 방식: 운영자 검토

1. 중국 출시 및 글로벌 대응 항목의 동일성을 확인합니다. 공식 매핑이 없으면 외형·구성·획득 유형을 대조하고 연결 근거를 남깁니다.
2. 같은 콘텐츠 계열·획득 방식·버전 전제의 검증된 과거 사례를 비교합니다. 중국 전체에 일괄적으로 일정 개월을 더하지 않습니다.
3. 시즌, 명절, 콜라보, 글로벌 구성 변경 가능성을 기록합니다. 이는 고려 요소이며 해당 게임의 확정된 운영 패턴이라는 뜻이 아닙니다.
4. 근거가 허용하는 월·범위·버전까지만 제시합니다. 비교 자료가 부족하면 일정 미정으로 둡니다.
5. 두 언어로 이유와 전제를 작성하고 검토 예정일을 지정합니다. 공개 후 공식 발표나 관련 변경 시 재검토합니다.

| 수준 | 편집 기준 | 화면 |
| --- | --- | --- |
| 근거 충분 / Supported | 동일성이 검토되고, 직접 관련된 글로벌 맥락과 복수의 비교 사례가 전제를 뒷받침하며 중대한 모순이 없음 | 예상 범위 + 구체 근거; 공식 확정으로 승격하지 않음 |
| 근거 제한적 / Limited | 합리적 단서가 있지만 비교 사례가 적거나 순서·지역 적용이 불확실함 | 더 넓은 예상 범위/버전 + 남은 불확실성 |
| 근거 부족 / Insufficient | 중국 출시 사실 외에 시기를 좁힐 근거가 없음 | 날짜 없이 ‘일정 미정’; 날짜형 예상은 공개하지 않음 |

이 수준은 확률이 아니라 편집상 근거 평가입니다. 실제 비교 자료를 수집하기 전에는 어느 외관에도 가짜 예상 날짜를 채우지 않습니다. 초기 시드에서는 검증된 글로벌 공식 일정과 중국 출시 기록을 먼저 확보하고, 방어 가능한 예상만 추가합니다.

### 변경 처리

- 공식 발표 시 별도의 공식 이벤트를 추가하고 기존 예상은 `superseded`로 남깁니다. 처음부터 맞힌 것처럼 과거 값을 고치지 않습니다.
- 예상 만료·검토 기한 경과 시 재검토 배지를 표시하고, 기한과 다음 검토를 편집 작업 목록에 올립니다.
- 판단이 무효해지면 `withdrawn`과 이유를 기록합니다. 날짜가 지났다고 ‘출시됨’으로 바꾸지 않습니다.
- 추후 자동 추정 도입 시 같은 유형의 검증된 대응 사례 최소 5개를 탐색 시작 기준으로 삼되, 충분한 신뢰를 뜻하지는 않습니다. 홀드아웃 검증, 구간 적중률, 오차, 표본 수를 보고한 후 도입을 결정합니다.

## 6. 사진·영상 운영

- 실제 게임 외관 자료만 사용합니다. AI 생성 이미지나 합성 예상도는 외관 증거로 사용하지 않습니다.
- 기본은 공식 원문/허용된 영상 임베드와 직접 촬영 또는 재사용 허락을 확보한 이미지입니다. 공개 URL과 출처 표기만으로 복제 권한이 있다고 가정하지 않습니다.
- 외부 영상은 제공자의 지원 방식으로 재생하고 실패 시 원문 링크를 제공합니다. 제3자 영상 다운로드·재업로드를 기본 수집 방식으로 삼지 않습니다.
- 저장할 이미지에는 원문, 권리자/제공자, 허가 또는 이용 조건, 편집 여부, 서버/버전, 양언어 설명을 연결합니다. 썸네일에도 같은 원칙을 적용합니다.
- 스크린샷은 사용자 ID·채팅 등 불필요한 개인정보를 가리고, 원본 외형을 왜곡하지 않는 범위에서 편집 여부를 알립니다.
- 사이트 대표 이미지는 최적화된 크기로 제공하고 미디어 비율을 예약해 레이아웃 흔들림을 줄입니다. 실제 영상·이미지 파일은 Git 저장소에 대량으로 넣지 않습니다.
- 삭제 요청 경로는 소개 페이지에 둡니다. 담당 연락 경로를 실제로 정하기 전에는 이메일 주소를 만들거나 가짜 폼을 게시하지 않습니다.

## 7. 편집 흐름

`발견 → 출처 확인 → 외관 연결 → 미디어 확인 → 영어·한국어 작성 → 데이터 검증 → 미리보기 → 게시 → 후속 정정`

초기에는 관리자가 저장소의 구조화된 콘텐츠와 미디어 참조를 수정하고 영어 PR로 변경을 검토합니다. 공개 방문자의 제보는 별도 초안으로 받아 검증 후 반영합니다. 비공개 저장소의 이슈 페이지를 공개 제보 창구로 링크하지 않습니다. 공개 전 별도 공개 제보 공간 또는 실제 연락 경로 중 하나를 연결합니다.

새 공지를 발견하면 관련 기존 기록과 예상도 함께 검토하는 것을 운영 목표로 둡니다. 24~48시간 내 반영을 내부 목표로 삼을 수 있지만 자동 모니터링이나 보장된 서비스 수준은 아직 없습니다. 출처·번역·상태 수정은 Revision으로 남기고 다음 배포에 포함합니다.
