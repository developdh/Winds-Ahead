# 디자인·반응형·속도 기준

[English](../en/design-quality.md) · [제품 기획](product-plan.md)

**사용자 요구:** 개발 기간이 늘어나더라도 디자인, UI/UX, 다양한 화면 크기에서의 사용성, 조작 반응 속도를 높은 우선순위로 둡니다. 이 문서는 목표와 검증 방법이며 아직 측정된 성능 결과는 아닙니다.

## 1. 기능마다 함께 완성할 항목

외관 도감·상세·캘린더를 각각 `정보 구조 → 시각 디자인 → 상호작용 → 반응형 → 접근성 → 성능 확인` 순서로 다듬습니다. 마지막 단계에 한 번에 보정하는 방식으로 미루지 않습니다. 핵심 동선의 문제가 남으면 원인을 수정하고 해당 흐름을 다시 확인합니다.

M1에는 실제 자료를 사용한 세 핵심 화면의 디자인과 클릭 가능한 프로토타입을 포함합니다. M2와 M3는 해당 화면의 반응형·사용성·속도 확인까지 완료 범위로 삼습니다. M4는 전체 동선과 배포 환경에서의 통합 확인에 집중합니다.

## 2. 시각·사용성 원칙

- 실제 외관의 실루엣·재질·색을 읽을 수 있도록 이미지 비율과 크롭을 설계합니다. 상세에는 전체 모습과 확대 보기를 제공합니다.
- **미리보기 선택:** 확인된 여성 외형 사진이 있으면 여성을 우선합니다. 테두리가 있는 합성 포스터보다 개별 사진이나 인물 중심으로 자른 구도를 사용합니다. 여성 이미지가 없거나 외관의 핵심 특징을 보여주기 어려운 경우에만 다른 구도를 선택합니다. 확대 갤러리에서는 원본 전체를 유지하며 파일명만으로 성별을 추정하거나 없는 외형을 만들지 않습니다.
- 먹빛·청옥 방향을 공통 색상, 글자 크기, 간격, 테두리, 상태 표시로 일관되게 적용합니다. 장식이 이름·출처·일정을 가리지 않게 합니다.
- 검색, 관심 저장, 필터 변경, 갤러리 조작은 즉시 시각적 반응을 줍니다. 오래 걸리는 작업에는 진행 상태와 재시도 경로를 제공합니다.
- 한글 입력기의 조합 중에는 검색어를 잘라 처리하지 않습니다. 뒤로 가기와 언어 전환 시 필터·월·목록 위치를 가능한 한 유지합니다.
- 체형/염색 조건, 공식/예상/미정 상태를 사진을 감상하는 흐름 안에서 자연스럽게 확인할 수 있게 합니다.
- 로딩·빈 결과·에러·미디어 차단·관심 저장 실패도 정상 화면과 같은 수준으로 디자인합니다.

## 3. 반응형과 접근성

| 확인 항목 | 기준 |
| --- | --- |
| 화면 크기 | 320, 360, 390, 768, 1024, 1440 CSS px와 사이 구간을 확인 |
| 모바일 캘린더 | 읽을 수 있는 목록형 기본 보기, 월 이동과 상태 필터를 엄지로 조작 |
| 모바일 상세 | 사진 → 이름/상태 → 핵심 정보 순서; 데스크톱 열을 단순 축소하지 않음 |
| 터치 | 주요 버튼은 44×44 CSS px를 프로젝트 목표로 두고 충분한 간격 제공 |
| 글자 | 본문 16px 이상, 일반 라벨 14px 이상; 한국어·영어 긴 이름과 200% 확대 확인 |
| 키보드 | 검색·필터·사진 확대·닫기·관심 저장 가능, 포커스 표시와 복귀 확인 |
| 움직임 | 움직임 줄이기 설정 준수, 자동 재생·불필요한 지속 애니메이션 제외 |
| 브라우저 | Chromium, Firefox, WebKit에서 확인; 실제 iOS/Android 장치 확인 여부는 별도 기록 |

가로 스크롤, 잘린 이름, 겹친 배지, 손가락으로 누르기 어려운 필터를 완료로 처리하지 않습니다. 자동 검사만으로 사용성을 확인했다고 주장하지 않습니다.

## 4. 속도 목표와 측정

실사용 성능 목표는 모바일·데스크톱을 나누어 75백분위에서 **LCP ≤ 2.5초, INP ≤ 200ms, CLS ≤ 0.1**입니다. 이는 [Core Web Vitals 권장 기준](https://web.dev/articles/vitals)을 채택한 목표입니다. 공개 전에는 제어된 느린 네트워크·CPU 조건에서 측정하고, 실제 운영 표본을 확보한 후 실사용 목표 달성 여부를 판단합니다. Lighthouse 점수만으로 실사용 INP나 전체 UX를 통과 처리하지 않습니다.

프로젝트의 초기 전송량 목표는 대표 탐색/상세 페이지에서 첫 로드 JavaScript 압축 합계 200KB 이하, 첫 화면 이미지 합계 600KB 이하입니다. 요청별 전송량을 기록하고 초과 시 원인을 분석합니다. 화질·한글 가독성을 해치는 압축으로 숫자만 맞추지 않습니다. 기준을 변경할 때는 비교 결과와 이유를 PR에 남깁니다.

- 큰 원본 대신 표시 크기에 맞는 이미지와 지원 형식/대체 형식을 제공합니다. 첫 핵심 이미지는 우선 로드하고 화면 밖 이미지는 지연 로드합니다.
- 사진 영역 크기를 미리 예약하고 폰트 교체 시 위치가 흔들리지 않게 합니다. 한국어 폰트의 실제 전송량도 확인합니다.
- 영상 플레이어와 무거운 갤러리 기능은 필요할 때 불러옵니다. 최초 방문 때 모든 영상을 내려받지 않습니다.
- 읽기 중심 페이지와 캘린더는 검증된 콘텐츠를 캐시해 제공합니다. AI API 호출은 게시 파이프라인에서 수행하며 방문자 요청의 대기 조건으로 두지 않습니다.
- 필터·월 이동은 대표 데이터와 확장된 시험 데이터로 반복 조작해 지연과 버벅임을 확인합니다.

## 5. 완료 증거

UI 변경 PR에는 주요 화면의 한국어·영어 모바일/데스크톱 캡처, 확인한 핵심 동선, 장치·브라우저·네트워크 조건, 성능 측정과 남은 제한을 남깁니다. 반복 측정은 같은 조건에서 수행하고, 실제 장치와 모의 실행을 구분합니다. 콘텐츠 갱신 PR은 이미지 크기·번역 누락·레이아웃 영향처럼 해당 변경이 일으킬 수 있는 회귀를 확인합니다.


## 선택한 시각 방향 · 2026년 9월 13일

사용자의 최신 방향은 어두운 톤을 유지하며 조작 수를 줄이되 시각적 완성도를 높이는 것입니다. 주요 동선은 외관과 캘린더 두 가지입니다. 큰 사진·절제된 면·정보의 위계·차분한 모션으로 디자인하며 단순화를 밋밋한 화면으로 해석하지 않습니다.

본문과 조작 요소는 고운 돋움의 기본 400 굵기를 그대로 사용하며 굵기를 합성하지 않습니다. 제목은 Noto Serif KR 500을 유지합니다. 랜딩은 Noto Serif KR 500으로 무협 정체성을 살리고, 배경에 스며드는 하나의 외관 사진과 얇은 선·화살표가 있는 세로 언어 선택 두 개를 둡니다. 선택한 언어는 저장합니다. 라이선스를 유지한 서브셋은 Winds Heading·Winds UI로 이름을 바꾸고 OFL 고지를 보존합니다.

모바일도 하단 부유 메뉴 대신 상단의 두 동선을 사용합니다. 사진과 핵심 사실을 먼저 보여주며 출처 이력은 펼쳐 읽고 캘린더 형태는 화면 너비에 맞춰 바뀝니다. 부드러운 등장·이미지 확대·출처 펼침·갤러리 전환·마우스와 키보드 초점 반응을 사용하며 동작 줄이기에서 효과를 끕니다. 재방문마다 최초 소개 화면으로 지연시키지 않습니다.

모든 화면 너비에서 상단 홈 로고는 한 글자 鏡으로 통일하고 접근성 이름에는 전체 브랜드를 유지합니다. 언어 전환은 오른쪽 끝에 둡니다.

로고와 주 메뉴는 한 묶음으로 가깝게 배치하며 헤더 간격과 메뉴 여백을 중복 적용하지 않습니다. 언어 버튼은 글자를 가운데 두고 44×44 전체 영역에 마우스·키보드 초점 반응을 적용합니다. 종류 필터를 바꾸면 이전 결과와 겹치는 외관을 포함해 결과 카드 전체가 다시 등장합니다.

모바일은 헤더 아래 콘텐츠 여백 24px, 소개와 도구 사이 20px, 검색과 종류 선택 사이 4px로 구성합니다. 검색과 주요 버튼의 터치 영역은 유지합니다. 390px 화면에서 첫 외관 사진의 시작 위치가 상단 약 408px에서 333px로 올라오며 데스크톱 여백은 유지됩니다.
